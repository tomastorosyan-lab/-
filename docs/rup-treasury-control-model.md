# Модель казначейского контроля небюджетных РУП

## Цель

Дать казначейству контроль финансовых потоков республиканских унитарных предприятий, **не переводя** их в статус бюджетных организаций.

РУП остаётся хозяйствующим субъектом. Меняется не право собственности и не оргформа, а **режим распоряжения деньгами**: счета в контуре, план как лимит, платёж только после акцепта.

## Ключевой принцип

Казначейство проверяет **соответствие** утверждённому финансовому плану (ФП), лимитам, реквизитам и запретам — а не «целесообразность» коммерческих решений. Внутри открытых лимитов предприятие работает самостоятельно.

## Четыре уровня контроля

### 1. Счета

- Все расчётные счета РУП — только в контуре казначейства / уполномоченного банка.
- Внеконтурные счета запрещены либо допускаются по спецразрешению с лимитом и отчётностью.
- Казначейство ведёт реестр счетов и видит остатки онлайн.

### 2. Финансовый план = лимит

- Утверждённый ФП (отраслевой орган) загружается в систему как лимиты обязательств и платежей по статьям и периодам.
- Казначейство открывает / блокирует / перераспределяет лимиты по согласованному порядку.
- Платёж сверх свободного лимита невозможен.

### 3. Реестр платежей (ядро контроля)

1. РУП регистрирует обязательство (договор / основание) с привязкой к статье ФП.
2. Формирует **заявку на платёж** (сумма, реквизиты, основание, статья, срок).
3. Система выполняет автопроверки; при необходимости — ручной акцепт казначейства.
4. Акцептованный реестр уходит в банк.
5. Банк исполняет **только** акцептованные позиции.

### 4. Доходы и мониторинг

- Поступления — на контрольные счета с идентификацией плательщика.
- Сверка с планом доходов, контроль кассовых разрывов, картотека неисполненных, отклонения от ФП.

## Роли

| Участник | Функция |
|---|---|
| РУП | ФП, договоры, заявки, первичная отчётность |
| Отраслевой орган | Утверждение ФП, целевые указания, согласование перераспределений |
| Казначейство | Лимиты, акцепт, блокировки, мониторинг потоков |
| Банк | Техническое исполнение по акцептованному реестру |

## Автопроверки заявки

- сумма ≤ свободный лимит статьи и периода;
- достаточность остатка / кассовый план;
- основание зарегистрировано;
- реквизиты валидны;
- нет блокировок / запретов / нецелевых статей;
- нет дубля оплаты того же основания.

## Исключения (контур не ломают)

| Тип | Режим |
|---|---|
| Зарплата, налоги, взносы | Упрощённый / пакетный реестр по графику |
| Срочные платежи | Ускоренный акцепт + постконтроль |
| Валюта / ВЭД | Отдельный контур счетов и согласований |
| Внеконтурный счёт | Только спецразрешение + лимит + отчётность |

## Объекты данных (MVP)

Цепочка: `Enterprise` → `Account` → `FinancialPlan` → `Limit` → `Obligation` → `PaymentRequest` → `Acceptance` → `BankExecution`

| Объект | Назначение | Ключевые поля |
|---|---|---|
| `Enterprise` | РУП в контуре | УНП, наименование, отраслевой орган, статус |
| `Account` | Расчётный счёт в контуре | номер, банк, валюта, режим (обычный / спец), остаток |
| `FinancialPlan` | Утверждённый ФП на период | период, версия, статус утверждения, орган |
| `Limit` | Лимит по статье ФП | статья, период, сумма плана, зарезервировано, оплачено, свободно |
| `Obligation` | Договор / основание расхода | номер, контрагент, сумма, статья ФП, срок |
| `PaymentRequest` | Заявка на платёж | сумма, реквизиты, основание, статья, счёт списания, срок |
| `Acceptance` | Решение казначейства | результат, причина отказа, кто/когда |
| `BankExecution` | Исполнение банком | статус банка, платёжка, факт списания |

Правило лимита: `свободно = план − зарезервировано − оплачено`. При подаче заявки сумма резервируется; при отказе/возврате — освобождается; при исполнении — переходит в «оплачено».

## Статусы заявки (`PaymentRequest`)

```
draft → submitted → auto_checked
                         ├─ pending_review → accepted | rejected
                         └─ accepted (если автоакцепт)
accepted → sent_to_bank → executed | returned
```

| Статус | Кто | Что происходит |
|---|---|---|
| `draft` | РУП | Черновик, лимит ещё не резервируется |
| `submitted` | РУП | Подана; сумма резервируется по статье |
| `auto_checked` | Система | Прошли/не прошли автопроверки |
| `pending_review` | Казначейство | Нужен ручной акцепт |
| `accepted` | Казначейство / авто | Можно отправлять в банк |
| `rejected` | Казначейство | Отказ с причиной; резерв снимается |
| `sent_to_bank` | Система | В реестре на исполнение |
| `executed` | Банк | Списано; резерв → оплачено |
| `returned` | Банк | Не исполнено; резерв снимается |

## Контур MVP (пилот)

1. Один пилотный РУП, рублевые счета в контуре.
2. ФП → лимиты по укрупнённым статьям.
3. Заявки + автопроверки + ручной акцепт.
4. Выгрузка акцептованного реестра в банк (файл / канал).
5. Без валюты, внеконтурных счетов и срочного контура на первом этапе.

## Что даёт модель

- прозрачные остатки и платежи РУП в онлайн;
- невозможность вывести средства на неконтролируемый счёт без спецрежима;
- кассовый план республики по внебюджетным потокам;
- сохранение хозяйственной самостоятельности внутри лимитов ФП.

## Следующие шаги после MVP

1. Нормативная рамка (что утверждается НПА, что — регламентом казначейства).
2. Детализация статей ФП и правил перераспределения.
3. Онлайн-интеграция с банком (вместо файлового реестра).
4. Расширение на зарплату/налоги, срочные платежи, валюту.
